# VFX Graph authoring from code

Copied from Soulbound's CLAUDE_VFX.md (written on Unity 6.5 / VFX 17.5). This project runs Unity 6000.6.8f1 with VFX Graph 17.6.0; see the section below for what changed.

## Unity 6.6 / VFX Graph 17.6 (checked 2026-11-09)
- No public authoring API and no Unity CLI (`pipeline`) commands for VFX Graph; the CLI only has shader commands (`shader`, `list_shaders`, `get_shader_properties`). Authoring is still by reflection from `script eval`.
- `VisualEffectResourceExtensions.GetOrCreateGraph(resource)` is gone: use `GetGraph(resource)`, and `CreateGraph(resource)` when it returns null.
- Unchanged: `VisualEffectAssetEditorUtility.CreateNewAsset(path)`, `VFXModel.AddChild(model, index, notify)`, `VFXContext.LinkTo(target, from, to)`, `SetSettingValue`, `VFXGraph.SetExpressionGraphDirty()`, `WriteAssetWithSubAssets(resource)`.
- Alternative to reflection: the package grants `InternalsVisibleTo("Unity.Testing.VisualEffectGraph.Editor")` (and other test assembly names), so an editor-only asmdef with that name can call the internal model API directly at compile time.
- Operators/blocks present: `SampleTexture2D`, `SampleMesh`, `Random`, `Condition`, `Branch`, `Step`, `Multiply`, `Add`, `Subtract`, `Divide`, `Lerp`, `Swizzle`, `AppendVector`, `Normalize`, `SetAttribute`, `Orient`, `PositionSequential`; outputs `VFXPlanarPrimitiveOutput`, `VFXMeshOutput`, `VFXComposedParticleOutput`, `VFXShaderGraphParticleOutput`.

### Lessons from building Grass.vfx (2026-11-09; builder: `Tools/VFX/GrassVfx.eval.cs`, run with `script eval --code`)
- Operators default to single floats: call `SetOperandType(index, typeof(Vector2/3))` (cascaded ops like Multiply, Divide) or `SetOperandType(typeof(...))` (Random). A float Divide on a UV quietly gives every particle u == v.
- Two separate `Random` operators produce the SAME sequence per particle (diagonal patterns). Use one multi-component Random.
- `Swizzle` reads a Vector4; a Vector2 linked into it loses its second component, and a Vector3 loses its z. Pad to a Vector4 first (AppendVector with SetOperandType(0, Vector3) + a 0) or use a Vector4 Random, then swizzle.
- Reading `position` back (Get Attribute) in Initialize after a random Set Attribute gave an unrelated value: build the position from the same randoms instead.
- `position` isn't per-channel: a "Y only" Set Attribute overwrites all three. Build the full vector (AppendVector + AddOperand).
- Static particles need an Update context anyway, or Automatic bounds never compute and everything is culled. Fixed bounds (Initialize `bounds` slot, an `AABox` with `center`/`size`, `boundsMode` Manual) are simplest for a field of known size.
- A link the graph refuses is silent: check `HasLink` after linking (the builder throws).
- To see a VFX in a test render, put it on its own layer and render only that layer. To test a texture-driven effect, feed it a constant texture first (proves the sampling and the effect), then check the coordinates.
- Fixed facing without turning to the camera: Orient `Advanced`, axes `YZ`, Y = ground normal, Z = a per-particle direction stored in `velocity` (Update has integration off). Two outputs, the second with Z = normal x facing, make a crossed tuft.

- Lit, shadowed particles need a Shader Graph with the URP Lit target and "Support VFX Graph" on. On the current integration such a graph renders ONLY through `VFXComposedParticleOutput` with `m_Topology` (e.g. `ParticleTopologyMesh`, field `MeshCount`) and `m_Shading` (`ParticleShadingShaderGraph`, field `shaderGraph` = the `ShaderGraphVfxAsset` sub-asset). Plain Mesh/Quad outputs with a `shaderGraph` setting compile no render shader at all (error "convert this context to dedicated ShaderGraph Output"). Alpha clip comes from the graph; `castShadows` is an output setting. Graph properties appear as output slots by reference name (`_Color`).
- Shader Graphs are generated by `Tools/VFX/make_grass_shadergraph.py` from the VFX sample `SG_Chomper_Feathers_XLit` (URP Lit + VFX, alpha clip): keeps the block nodes, a Color property and one texture sample, adds Color x texture into Base Color.
- Built-in time: `VFXDynamicBuiltInParameter` with `m_BuiltInParameters` = `VfxTotalTime`.

# Soulbound notes (Unity 6.5 / VFX 17.5)

Living knowledge base for building `.vfx` assets from code (via the live-editor CLI `eval_file`). Append as we learn. Companion: `CLAUDE_SGraph.md` (Shader Graph). See also memory `vfx-shadergraph-workflow`.

## The #1 workflow rule (dev directive)
After **every** change to a VFX (or Shader) graph: **check the console for errors → fix ALL → re-check → repeat until 0 errors → THEN test/render.** A graph with a silent error compiles to an output that renders **nothing** (blank frame). Blank is a real failure, not a tooling blind spot — `capture_game_view` DOES capture VFX correctly (verified against the dev's own eyes).

Concretely: `clear_console` → build/save the graph → force-reimport the asset → `get_console_logs` (filter Error/Exception). Note: slot-value errors are logged by VFX internally (they do **not** throw up into the eval), so a build can report "SAVED" while an attribute silently stayed at default — always read the console after building, not just the eval return.

## Reflection entry points (all internal; use reflection from eval_file)
Assemblies: editor types in **`Unity.VisualEffectGraph.Editor`**, `VisualEffectResource` in **`UnityEditor.VFXModule`**.
- Create asset: `UnityEditor.VisualEffectAssetEditorUtility.CreateNewAsset(string path)` → `VisualEffectAsset` (creates an **empty** graph, 0 contexts).
- Get resource: `UnityEditor.VFX.VisualEffectResource.GetResourceAtPath(path)` (static, in VFXModule).
- Get graph: `VisualEffectResourceExtensions.GetOrCreateGraph(resource)` → `VFXGraph`.
- Save: `VisualEffectResourceExtensions.WriteAssetWithSubAssets(resource)`, then `EditorUtility.SetDirty(resource)` + `AssetDatabase.SaveAssets()` + `AssetDatabase.ImportAsset(path, ForceSynchronousImport|ForceUpdate)`. Call `graph.SetExpressionGraphDirty()` before writing.

## Building the graph
Base model type `UnityEditor.VFX.VFXModel` (BindingFlags Public|NonPublic|Instance):
- Instantiate a node/block: `ScriptableObject.CreateInstance(type)`.
- Parent it: `model.AddChild(VFXModel child, int index=-1, bool notify=false)`.
- Remove (for rebuilds): `model.RemoveChild(child, false)`.
- Settings (enums/bools/strings): `model.SetSettingValue(string name, object value)`. For enums, read the field's `FieldType` off the instance and `Enum.Parse` — the enum types live in odd namespaces, don't hardcode.
- `children` / `position` (Vector2, editor layout) are `VFXModel` properties.

Contexts (`UnityEditor.VFX.VFXContext`): `VFXBasicSpawner`, `VFXBasicInitialize`, `VFXBasicUpdate`, outputs incl. `VFXPlanarPrimitiveOutput` (the unlit Quad/Triangle/Octagon output), `VFXComposedParticleOutput` (configurable shading), `VFXMeshOutput`, etc.
- Flow-link: `ctx.LinkTo(VFXContext target, int fromSlot=0, int toSlot=0)`. Chain spawner→init→update→output. Linking auto-creates & **shares** the `VFXDataParticle` across init/update/output (verify: `ctx.GetData()` returns the same instance for all three; spawner has its own data). `GetSystemNames` returning 2 systems (spawn + particle) is normal.

Blocks (`UnityEditor.VFX.VFXBlock`, namespace `UnityEditor.VFX.Block.*`):
- Spawner rate: `VFXSpawnerConstantRate` (rate = input slot 0).
- Attributes: `SetAttribute` — settings: `attribute` (string, e.g. "lifetime"/"velocity"/"size"/"color"/"alpha"/"position"), `Random` (Off/PerComponent/Uniform), `Composition`, `channels`. With Random=Off there's 1 value slot; with Random≠Off there are 2 (A=min, B=max).
- Forces/motion: `Turbulence`, `Gravity`, `Force`, `LinearDrag`. Position: `PositionShape` (composite Shape setting — fiddly; often easier to SetAttribute "position" with a small random box).
- Color/curve: `ColorOverLife` (slot 0 = `VFXSlotGradient`), `AttributeFromCurve` (defaults to attribute=position → 3 curve slots; set `attribute` setting first to change).

## Slot values — the big gotcha
`slot = blockAsIVFXSlotContainer.GetInputSlot(i)`; set `slot.value` (VFXSlot.value property). BUT many "vector-ish" attribute slots are **composite VFX value types**, not raw `UnityEngine.Vector3`, and assigning a Vector3 throws (logged) and leaves the default:
- **position** slot → `UnityEditor.VFX.Position` struct (has a Vector3 field).
- **velocity** random A/B slots → `UnityEditor.VFX.Vector` struct.
- direction-ish → `UnityEditor.VFX.DirectionType`.
- **color** slot → plain Vector3 (linear RGB) works directly. **alpha** → float. **size**/**lifetime** → float.

Robust pattern: a smart setter that inspects `slot.value`'s current type and, if the incoming value is a `Vector3`, wraps it into `Position`/`Vector`/`DirectionType` (each has one `Vector3` field found by reflection) before assigning. Floats/Color/Texture2D/Gradient assign directly.
- Texture: `VFXPlanarPrimitiveOutput` mainTexture is **input slot 0**, named `mainTexture`, and only exists when `useBaseColorMap != None`.
- **KNOWN-UNSOLVED:** assigning a `UnityEngine.Gradient` to `ColorOverLife`'s `VFXSlotGradient` (slot 0) silently fails → the gradient stays **empty** → since ColorOverLife *overwrites* color, particle color becomes **black** → **whole effect renders blank** (additive black = nothing). Workaround for now: set color in **Initialize** via `SetAttribute("color")` (Vector3) and skip ColorOverLife, OR find the correct gradient-assignment path (TODO: gradient may need a VFX wrapper type or `slot.value` via a different API). This single issue caused hours of "blank" chasing.

## Rendering gotchas (why "0 errors but blank")
1. **boundsMode = Recorded is the default** on a fresh `VFXDataParticle` → bounds are empty (never recorded) → the entire output is frustum-culled → renders nothing though particles are alive (`aliveParticleCount` > 0 in Play). **Fix: set the particle data's `boundsMode` setting to `Automatic`** (computes bounds from particles each frame). Get the data via `initCtx.GetData()`, find the bounds enum field, `SetSettingValue`. This is the most common invisible-VFX cause.
2. **Color never set** → additive black = invisible. `VFXPlanarPrimitiveOutput` is **unlit**, so with **Additive** blend the color is added straight to the framebuffer (emissive). If the color attribute stays at its default (black), you see nothing. Always set color (Initialize `SetAttribute("color")`), and push to **HDR (>1)** for glow/bloom in a dark scene — correct for a candle/fire.
3. `aliveParticleCount` returns **-1 in edit mode** (unreliable); it reports real counts in **Play mode**. Use Play mode to confirm simulation.
4. `useSoftParticle=true` needs a depth buffer — can render invisibly in some URP setups; leave **false** unless depth is available.

## Verify loop (headless)
1. Build+save `.vfx` (eval). 2. Reimport + **console error check → 0**. 3. `eval_file` scene setup: empty scene, MainCamera with dark solid bg, a `VisualEffect` GO with the asset, `Reinit()`, save scene. 4. `editor_play`. 5. wait ~2-3s. 6. `capture_game_view --save_path Assets/_bldtmp/x.png`. 7. Read the PNG (and/or analyze max/bright-pixel counts with PIL). 8. Iterate. Clean `Assets/_bldtmp/` when done. `eval_file` runs the code as a **method body** — no top-level `using` (use fully-qualified names); avoid nested multi-statement lambdas (they can throw "Compilation Failed"). Don't run `eval_file` while in Play mode if it needs to compile — stop play first.

## Exposed parameters (driving a graph from C#)
- Create: `ScriptableObject.CreateInstance(UnityEditor.VFX.VFXParameter)` → `param.Init(typeof(float))` → `AddChild(graph, param)` → `SetSettingValue("m_ExposedName", "SpawnRate")` + `SetSettingValue("m_Exposed", true)`; set the default on its **output** slot 0.
- Wire it into a block: `blockInputSlot.Link(paramOutputSlot, true)`.
- Read back at runtime with `vfx.HasFloat("Name")` / `SetFloat`. Verified working for `SpawnRate`, `Turbulence`, `SmokeRate`.

## Scaling a VFX (candle → bonfire from one graph)
- **`transform.localScale` DOES scale the whole sim** — *provided the systems are in `Local` space* (`initCtx.space`, default `Local`). Verified: scale 3 measured 3.29× the flame height of scale 1. No per-particle "Scale" param needed.
- **A `Light`'s `range`/`intensity` ignore transform scale** — scale them explicitly in C# if the fire's size changes. (A child light's local *offset* does scale with the parent.)

## Editor-scripting gotchas that cost hours (not VFX-specific, but they masquerade as VFX bugs)
1. **`EditorSceneManager.NewScene` can unload unreferenced assets.** An asset reference loaded *before* NewScene can become a destroyed (fake-null) object; assigning it then silently writes **null**. **Always `LoadAssetAtPath` AFTER creating/opening the scene.** This is nondeterministic — it "works" until it doesn't.
2. **Raw reflection writes to a prefab-instance field are not registered as prefab overrides** and get reverted when the scene is saved or reloaded (entering play mode reloads it) — you silently get the prefab's default value back. Use `SerializedObject`/`FindProperty`/`ApplyModifiedProperties` (what the Inspector does), or `PrefabUtility.UnpackPrefabInstance(...Completely...)` for throwaway preview scenes. (Inspector edits by a human are unaffected — this is a scripting-only trap.)
3. When a headless render "doesn't change", **verify the state you think you set** (read the field back and print it) before re-tuning the art. Three tuning rounds here were spent on a value that was never applied.

## A working candle-flame recipe (renders, verified)
Spawner ConstantRate ~160 → Initialize: SetAttribute lifetime(rand 0.4–0.75), position(rand box ±0.012 disc), velocity(rand up ~0.28–0.46, tiny xz spread), size(rand 0.03–0.07), color(HDR ~(3.2,1.35,0.35)), alpha(~0.9) → Update: Turbulence (subtle flicker) → Output VFXPlanarPrimitiveOutput: Quad, **Additive**, useBaseColorMap=ColorAndAlpha + soft radial mainTexture, **boundsMode Automatic**. Gives a soft glowing upward flame. TODO polish: teardrop taper (size-over-life), true hot→red color-over-life (blocked on the gradient-slot issue), fewer gaps (higher rate / less turbulence).
